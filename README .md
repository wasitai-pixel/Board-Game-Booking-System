## 2. `realgame.c` — ระบบจองบอร์ดเกมห้องสมุด

### 2.1 คอมไพล์และรัน

```bash
gcc -O2 -std=c11 realgame.c -o boardgame -lm
./boardgame
```

บน Windows ให้พิมพ์ `chcp 65001` ก่อนรัน เพื่อให้แสดงภาษาไทยได้ถูกต้อง
(`-lm` จำเป็นเพราะใช้ฟังก์ชัน `log()` ในส่วนทดสอบ Big-O)

### 2.2 กติกาของระบบ

- มีบอร์ดเกม **10 เกม** (รหัส `AB001`–`AB010`) แบ่งเป็น 5 คู่ เกมคู่เดียวกันถือเป็น "เกมใกล้เคียง"
- มีโต๊ะ **6 โต๊ะ**: โต๊ะใหญ่ 2 โต๊ะ (7–10 คน) และโต๊ะเล็ก 4 โต๊ะ (2–6 คน)
- กลุ่มที่มี 7 คนขึ้นไปได้เฉพาะโต๊ะใหญ่ กลุ่มที่เล็กกว่านั้นได้เฉพาะโต๊ะเล็ก
- จำนวนคนต่อกลุ่ม 2–10 คน
- ต้องคืนเกมก่อน **15:30 น.** — จองเวลา 15:30 เป็นต้นไปไม่ได้
- รองรับการจองได้สูงสุด 200 รายการพร้อมกัน (`MAXB`)

### 2.3 เมนูการใช้งาน

| เมนู | การทำงาน |
|---|---|
| 1 | ค้นหา/จองเกม — ค้นด้วยรหัสหรือชื่อ (ไทย/อังกฤษ) แล้วจอง |
| 2 | ดูสถานะโต๊ะ |
| 3 | ดูสถานะบอร์ดเกม (ว่าง / ถูกจอง / กำลังใช้งาน) |
| 4 | ยืนยันการจอง (เปลี่ยนจาก "ถูกจอง" เป็น "กำลังใช้งาน") |
| 5 | ยกเลิกการจอง |
| 6 | คืนเกม |
| 7 | สถิติการยืม เรียงจากมากไปน้อย |
| 8 | ดูคิวรอโต๊ะ |
| 9 | ทดสอบ Big-O ที่ n = 1,000 / 10,000 / 100,000 |
| 0 | ออกจากโปรแกรม |

การยืนยัน/ยกเลิก/คืนเกม ต้องระบุรหัสการจอง (`#`) และพิมพ์ชื่อผู้จองให้ตรงกับที่จองไว้ (ไม่สนตัวพิมพ์เล็ก-ใหญ่)

### 2.4 โครงสร้างข้อมูลที่ใช้

**Max Heap สำหรับคิวรอโต๊ะ**
เมื่อโต๊ะเต็ม ผู้จองจะเข้าคิวใน Max Heap โดยกลุ่มที่ใหญ่กว่าได้สิทธิ์ก่อน
ถ้าขนาดเท่ากัน ใครจองก่อน (id น้อยกว่า) ได้ก่อน คำนวณจาก

```c
priority = size * 10000000 - id
```

ฟังก์ชันที่เกี่ยวข้อง: `hpush` (เพิ่ม), `hpop` (ดึงตัวบนสุด), `hremove` (ลบรายการที่ระบุ)
และ `assign()` ที่จัดโต๊ะให้กลุ่มใหญ่ที่สุดที่หาโต๊ะที่เหมาะสมได้ ทุกครั้งที่มีการจอง ยกเลิก หรือคืนเกม

**Sequential Search — `mySearch()`**
ค้นเกมแบบไล่ทีละตัว O(n) โดยตรงกับรหัสแบบเต็ม หรือมีคำค้นอยู่ในชื่อไทย/ชื่ออังกฤษ ไม่สนตัวพิมพ์เล็ก-ใหญ่

**Hash Table (open addressing, linear probing)**
ใช้ฟังก์ชันแฮช `djb2` ขนาดตารางเป็นกำลังของ 2 และไม่น้อยกว่า 2n (load factor ≤ 0.5)
ฟังก์ชัน: `hash_init`, `hash_put`, `hash_get`, `hash_free`

> **หมายเหตุ:** ในโหมดใช้งานจริง (เมนู 1–8) ระบบค้นเกมด้วย `mySearch()` (Sequential)
> ส่วน Hash Table ถูกใช้ในเมนู 9 สำหรับทดสอบประสิทธิภาพเท่านั้น

### 2.5 เมนู 9 — ทดสอบ Big-O

1. สร้าง Hash Table ที่มีข้อมูล `ผู้จอง0 ... ผู้จอง(n-1)` สำหรับ n = 1,000 / 10,000 / 100,000
2. ค้นหาชื่อที่ **ไม่มีในระบบ** 64 ชื่อ วนรวม 1,000 รอบ (กรณีไม่พบ ซึ่งเป็น worst case)
3. วัด 31 ครั้ง ทิ้งรอบแรก (warm-up) แล้วเลือกรอบที่เร็วที่สุดเพื่อลดสัญญาณรบกวน
4. คำนวณเลขชี้กำลัง `k = log(อัตราส่วนเวลา) / log(อัตราส่วน n)` แล้วประเมิน Big-O

| ค่า k เฉลี่ย | ผลประเมิน |
|---|---|
| < 0.3 | O(log n) หรือ O(1) |
| 0.3 – 0.7 | O(√n) |
| 0.7 – 1.3 | O(n) |
| ≥ 1.3 | O(n log n) หรือสูงกว่า |

Hash Table ที่ออกแบบถูกต้องควรได้ k ใกล้ 0 (คือ O(1))

## 3. ส่วนที่ `Hash.c` และ `timing_template.c` ใช้ร่วมกัน

ทั้งสองไฟล์อ่านไฟล์ข้อมูล ตรวจความถูกต้อง แล้ววัดเวลาเฉลี่ยต่อการค้นหาหนึ่งครั้ง
เทียบ 3 อัลกอริทึม:

1. `SequentialSearch` — ไล่ค้นทีละตัว O(n)
2. `BinarySearch` — ใช้กับข้อมูลที่เรียงแล้ว O(log n) (เรียงด้วย `qsort` ก่อน โดยไม่นับเวลา)
3. `MySearch` — Hash Table แบบ chaining O(1) โดยเฉลี่ย

### คอมไพล์และรัน

```bash
gcc -O2 Hash.c -o timing        # หรือ timing_template.c
./timing data_1000.txt targets_1000.txt
```

(บน Windows ใช้ `timing.exe data_1000.txt targets_1000.txt`)

### โครงสร้าง Hash Table

```c
#define HSIZE 262144      /* ใหญ่กว่า 2 เท่าของ MAXN */
int hhead[HSIZE];         /* ตำแหน่งตัวแรกของแต่ละช่อง, -1 = ว่าง */
int hnext[MAXN];          /* ตำแหน่งตัวถัดไปในช่องเดียวกัน (linked list ด้วย index) */
```

- ฟังก์ชันแฮช: `ค่า % HSIZE`
- `BuildHash()` สร้างตารางก่อนวัด **ไม่นับเวลา**
- `MySearch()` ไปที่ช่อง `target % HSIZE` แล้วไล่ chain หาค่าที่ตรง คืนตำแหน่งใน `data[]` หรือ `-1`
- ค่าติดลบคืน `-1` ทันที (ข้อมูลทดสอบเป็นจำนวนเต็มบวกอยู่แล้ว)

### ตัวจับเวลา `NowMs()`

ใช้ตัวจับเวลาละเอียดสูง: `QueryPerformanceCounter` บน Windows และ `clock_gettime(CLOCK_MONOTONIC)` บน Linux/Mac
(แทน `clock()` ที่บน Windows ละเอียดเพียง ~1 ms) แล้ววนค้นซ้ำ `REPEAT = 1000` รอบ
เพื่อให้วัดค่าเล็กมากได้ จากนั้นหารเฉลี่ยต่อการค้นหาหนึ่งครั้ง (หน่วย ms)

### ฟังก์ชัน `PrintCell()` — จัดคอลัมน์ภาษาไทย

`printf("%-10s")` นับความกว้างเป็น "ไบต์" แต่ตัวอักษรไทยกว้างไม่เท่าไบต์ (และสระ/วรรณยุกต์ไม่กินช่อง)
คอลัมน์ในตารางตรวจความถูกต้องจึงเบี้ยว `PrintCell(text, ความกว้างที่แสดงจริง, ความกว้างคอลัมน์)`
จึงเติมช่องว่างเองให้ครบ

### ตารางตรวจความถูกต้อง

แสดงผล "พบ/ไม่พบ" ของค่าที่ค้นหาทั้ง 10 ค่า ครบ 3 คอลัมน์ (Sequential, Binary, Hash)
ที่ถูกต้องต้องได้ **พบ 7 ไม่พบ 3** ตรงกันทั้งสามอัลกอริทึม

## 7. วิธีวัดผลตามกติกาและการแปลผล

### ขั้นตอนที่แนะนำ

1. รันกับ n = 1,000, 10,000 และ 100,000 ตามลำดับ
2. ตรวจตาราง "ความถูกต้อง" ก่อนเสมอ: ต้องพบ 7 ค่า ไม่พบ 3 ค่า
3. ใช้ `REPEAT` เดียวกันทุกการทดลอง (ค่าเริ่มต้น = 1000) และระบุในรายงาน
4. จดเวลาครั้งที่ 1–5 ตัดค่าสูงสุดและต่ำสุด แล้วเฉลี่ยจาก 3 ค่าที่เหลือ

### ตัวอย่างโค้ดเฉลี่ยแบบตัดค่าสูง-ต่ำ (ใช้แทนแถว Average ใน `timing_template.c`)

```c
double TrimmedAvg(double v[], int k)   /* k = TRIALS */
{
    double sum = 0, mx = v[0], mn = v[0];
    int i;
    for (i = 0; i < k; i++) {
        sum += v[i];
        if (v[i] > mx) mx = v[i];
        if (v[i] < mn) mn = v[i];
    }
    return (sum - mx - mn) / (k - 2);
}
```

เรียกใช้เป็น `TrimmedAvg(ms_seq, TRIALS)`, `TrimmedAvg(ms_bin, TRIALS)`, `TrimmedAvg(ms_my, TRIALS)`

### การแปลผล Big-O จากเวลาจริง

เมื่อ n เพิ่มจาก 1,000 เป็น 100,000 (เพิ่ม 100 เท่า) คำนวณ

```
k = log(เวลาที่ n=100000 / เวลาที่ n=1000) / log(100)
```

| อัลกอริทึม | k ที่คาดหวัง | ความซับซ้อน |
|---|---|---|
| Sequential | ≈ 1 | O(n) |
| Binary | ใกล้ 0 (≈ 0.1–0.2) | O(log n) |
| Hash Table | ใกล้ 0 | O(1) โดยเฉลี่ย |

## 8. ข้อควรระวัง

- **ตรวจความถูกต้องก่อนดูเวลาเสมอ** โปรแกรมที่ทำงานผิดมักเร็วกว่าโปรแกรมที่ทำงานถูก
- ไม่นับเวลาการอ่านไฟล์ การเรียงข้อมูล การสร้าง Hash Table และการแสดงผล
- ตัวเลขเวลาขึ้นกับเครื่อง ใช้เทียบเคียงระหว่างอัลกอริทึมบนเครื่องเดียวกันเท่านั้น
- ที่ n = 1,000 เวลาของ Binary และ Hash เล็กมาก (ระดับนาโนวินาทีต่อครั้ง) อาจแกว่งระหว่างรอบ จึงควรเฉลี่ยหลายครั้ง
- `Hash.c` พิมพ์ทศนิยมเพียง 6 ตำแหน่ง ค่าของ Hash ที่เล็กมากอาจแสดงเป็น `0.000000` ได้ ถ้าต้องการดูละเอียดให้ใช้ `timing_template.c` (9 ตำแหน่ง)
- `realgame.c` กับ `Hash.c`/`timing_template.c` เป็นโปรแกรมแยกกัน ผลวัดของ `realgame.c` (ค้นด้วยสตริง) ไม่ใช่ข้อมูลชุดเดียวกับของ `timing_template.c` (ค้นด้วยจำนวนเต็ม) จึงไม่ควรนำตัวเลขมาเทียบข้ามกัน
